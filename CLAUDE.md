# smnvda-site

Портфолио-резюме Дмитрия Семенова (бизнес-архитектор), домен **smnvda.ru**.
Astro + Tailwind CSS 4 + Alpine.js, статическая сборка, деплой на GitHub Pages через GitHub Actions.

## Текущее состояние

Одностраничное резюме на базе шаблона [Smilesharks/dev-portfolio](https://github.com/Smilesharks/dev-portfolio), наполненное реальными данными из резюме с hh.ru. Полностью заменило прежнее многостраничное портфолио (Astro + свой CSS, экспорт из Webflow) — та версия сохранилась только в истории git, на сайте её больше нет.

- **Весь контент — в `cv.json`** (формат jsonresume.org). Правки текста, опыта работы, навыков, образования, проектов делаются там, компоненты трогать не нужно.
- Секции сайта — `src/components/sections/*.astro` (Hero, About, Experience, Education, Skills, Projects), каждая читает свои поля из `cv.json` через алиас `@cv`. Все UI-заголовки русскоязычные: «Обо мне», «Экспертиза» (компонент Skills), «Опыт» (Experience), «Ключевые трансформации» (Projects), «Образование» (Education) — см. раздел «Композиционная переработка страницы».
- Тема: светлая/тёмная/системная + 5 цветовых схем (`default`, `blue`, `red`, `green`, `cyber`) — переключаются на клиенте (`ThemeSwitch.astro`, `localStorage`), поле `basics.theme` в `cv.json` на переключение не влияет.
- Версия для печати в PDF — через `@media print` стили в компонентах.
- Профиль: контакты — почта, телефон, Telegram, MAX — выводятся вертикальным списком «иконка + текст» (см. раздел «Блок контактов в Hero»). Иконки Telegram и MAX добавлены отдельно (`src/icons/Telegram.astro`, `src/icons/Max.astro`) — в оригинальном шаблоне были только GitHub/LinkedIn/X.
- Фото профиля: `public/smnvda.jpg` (реальное, перенесено из прежней версии сайта).
- Favicon: `public/favicon-16x16.png` / `favicon-32x32.png` (реальные, перенесены из прежней версии сайта) — generic favicon.svg из шаблона удалён.
- Заголовок вкладки браузера — просто `{name}` из `cv.json` (`Layout title={name}` в `index.astro`), без "Portafolio - ...".
- Убрана нижняя атрибуция автора шаблона ("Made by Ariel", `src/components/sections/Tail.astro` удалён), оранжевая подсказка "Press Cmd+K" (`KeyboardManager.astro` очищен от неё) и декоративный значок ⌘ в конце контактов Hero — командная палитра по Cmd/Ctrl+K продолжает работать, просто без визуальных напоминаний о себе.
- Деплой: `.github/workflows/deploy.yml` — при каждом push в `master` собирает Astro (`withastro/action`) и публикует в GitHub Pages (`actions/deploy-pages`). Использует npm (`package-lock.json`) — `pnpm-lock.yaml` из шаблона удалён, он ломал сборку (`withastro/action` выбирал pnpm без указанной версии).
- Кастомный домен: `public/CNAME` (`smnvda.ru`) + `site: "https://smnvda.ru"` в `astro.config.mjs`.
- Репозиторий публичный — приватным GitHub Pages с кастомным доменом не работает без платного плана. Вся история git проверена на секреты/утечки (API-ключи, пароли, `.env`) — ничего не найдено. В `cv.json` осознанно лежат реальные контакты (телефон, почта, Telegram, MAX) — это ожидаемо для публичного резюме, не утечка.

### Особенности вёрстки, обнаруженные по ходу
- В `Layout.astro` есть глобальный **`ul { list-style: none }` вне `@layer`** — он перебивает Tailwind-класс `list-disc` на `ul` (unlayered побеждает layered независимо от специфичности). Поэтому маркеры списков на сайте не отображались вообще, а правило `li::marker { color: var(--color-accent) }` в `Experience.astro` было мёртвым кодом. Обход: вешать `list-disc` на сам `li` (`[&>li]:list-disc`), глобальный сброс его не касается.
- В Achievements маркер сделан нейтральным через скоуп-правило `ul.achievements > li::marker { color: currentColor; font-size: 0.75em }`. Остальные списки (Summary, Responsibilities, Projects) остались без маркеров, как и были.

### Как проверять изменения вёрстки в этой сессии
Chromium предустановлен, но Playwright из `node_modules` ищет не ту сборку — запускать так:
```js
chromium.launch({ executablePath: '/opt/pw-browsers/chromium' })
```
Сценарий проверки: `npm run build` → `npx astro preview --port <порт>` → скриншоты секции в 4 комбинациях (desktop 1440 / mobile 390 × light / dark; тему выставлять через `localStorage.setItem('theme', ...)` в `addInitScript`). Обязательно проверять `document.documentElement.scrollWidth == clientWidth` (нет горизонтального overflow). В Experience достижения скрыты за кнопкой «Show more» — её надо кликнуть перед съёмкой.

Ориентиры по высоте секций (desktop 1440 / mobile 390) на текущем содержимом: Experience — первая карточка ~1266 / ~2088 px в раскрытом виде, Projects — ~1468 / ~2696 px, «Экспертиза» — ~368 / ~578 px.

## Композиционная переработка страницы (сессия от 2026-08-25)

Цель — чтобы страница за 20–30 секунд читалась как «кто я → чем занимаюсь → в чём экспертиза → где и на каком масштабе → какие трансформации реализовал → образование». Контент не менялся, только порядок, UI-заголовки и визуальный вес.

- **Порядок секций** (`src/pages/index.astro`, правая колонка): было Experience → Projects → Skills → Education, стало **Skills → Experience → Projects → Education**. Левая колонка (Hero → About → ThemeSwitch) не менялась. На печати порядок прежний: Skills и Projects скрыты (`print:hidden`), Education держит `order-first` и встаёт первым в print-грид.
- **UI-заголовки переведены на русский**: About → «Обо мне», Experience → «Опыт», Summary → «Кратко», Responsibilities → «Зона ответственности», Achievements → «Достижения», Projects → «Ключевые трансформации», Education → «Образование», Certificates → «Дополнительное обучение», Show more / Show less → «Подробнее» / «Свернуть». Профессиональные термины внутри контента (Operational Transformation Lead, BPMN, ArchiMate, As-Is / To-Be, названия систем) не переводятся. `Present` в датах и `Actual` в Education оставлены как есть.
- **Ранний опыт (начало до 2017: АШАН, Азбука вкуса, Глобалстрой-Инжиниринг)** визуально облегчён флагом `isEarly` в `Experience.astro` (константа `EARLY_EXPERIENCE_BEFORE = 2017`): заголовок `text-base` вместо `text-lg`, `pb-4` вместо `pb-6`, теги в нейтральном стиле (`SKILL_TAG_MUTED`, те же токены, что у secondary-группы в Skills), и свёрнутый блок без 50-пиксельного «пика» — `x-collapse.min.0px` вместо `x-collapse.min.50px`. По умолчанию у ранних позиций видны период, должность, компания, локация и «Кратко»; остальное — под «Подробнее». Тексты и данные не тронуты.
- ⚠️ **Почему `min.0px`, а не просто `x-collapse`**: без модификатора `min` Alpine-плагин collapse ставит элементу `display: none`, и `print:!h-auto` его уже не возвращает — обязанности и достижения ранних позиций пропадали из PDF. С `min.0px` элемент остаётся в потоке с нулевой высотой, а на печати разворачивается. Проверено экспортом PDF.
- Атрибут collapse задаётся спредом (`{...(isEarly ? { "x-collapse.min.0px": true } : ...)}`), потому что модификаторы Alpine — часть имени атрибута и динамически не подставляются.

Замеры после переработки (свёрнутое состояние): секции desktop 1440 — Обо мне 446, Экспертиза 368, Опыт 1941, Ключевые трансформации 1468, Образование 356 px; mobile 390 — 425 / 578 / 2413 / 2732 / 616 px. Карточки опыта desktop: 2023+ 324 px против 226–244 px у ранних. Горизонтального overflow нет ни в одной из 4 комбинаций (desktop/mobile × light/dark), print-версия не изменилась.

## Блок контактов в Hero (сессия от 2026-08-25)

Был горизонтальный ряд иконок-кнопок (почта пряталась за кнопкой копирования с тултипом «Copied!», телефон и Telegram — просто иконки). Стал вертикальный список «иконка + текст»: рекрутер видит и копирует значения, не наводя мышь.

- Разметка — `<footer class="no-print contacts">` в `Hero.astro`: по строке на контакт, каждая — `.contact` с `.contact-icon` (фиксированный бокс `width: 1rem`, `flex: none`, акцентный цвет) и `.contact-value` (обычный текст, `--color-text-muted`). Текст всех строк начинается на одной вертикали.
- `flex-direction: column` задан без медиазапросов — ряд не должен возвращаться ни на каком размере экрана.
- Ссылки остаются, но как дополнительная функция: `mailto:`, `tel:` (в href только цифры — `phoneHref`, на экране номер как в `cv.json`), `t.me`. Кнопок «Copy» нет: текст выделяется мышью. На ссылках стоит `draggable="false"` — иначе Chrome при протягивании по тексту начинает drag&drop ссылки вместо выделения.
- Профиль без `url` рендерится не ссылкой, а `<div>` (динамический тег `const Tag = url ? "a" : "div"`); поэтому `display: inline-flex` прописан прямо в `.contact`, а не наследуется от правила `footer a`.
- Идентификаторы вместо названий сетей (`contactLabel`): Telegram — `@username`, MAX — `MAX: <номер телефона из basics.phone>` (в MAX аккаунт привязан к телефону; если задан свой `username`, приоритет у него). Клик по строке MAX ведёт на тот же `tel:`, что и телефон, — отдельной ссылки на профиль в данных нет.
- В `SOCIAL_ICONS` есть фолбэк `?? Contact` (`src/icons/Contact.astro`) для сетей без своей иконки.
- Печать не затронута: контакты в `.no-print`, печатный футер по-прежнему выводит `email • phone` одной строкой.

Замеры: строки по 24 px с интервалом 2 px, блок 102 px на desktop и mobile, горизонтального overflow нет ни в одной из 4 комбинаций.

## Миграция хостинга: Cloudflare → GitHub Pages + Jino DNS

Сайт переехал с Cloudflare (Pages + DNS) на:
- **Хостинг** — GitHub Pages
- **DNS** — регистратор **Jino.ru** (домен `smnvda.ru`), Cloudflare полностью убран

### Статус: миграция завершена
- NS-делегация на уровне регистратора переключена на `ns1-4.jino.ru` (было `khalid.ns.cloudflare.com` / `sharon.ns.cloudflare.com`), статус `DELEGATED` — подтверждено в реестре доменных имён
- A-записи корневого домена в Jino указывают на 4 IP GitHub Pages: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
- Сертификат выпущен, **Enforce HTTPS включён** в Settings → Pages — подтверждено пользователем в инкогнито-режиме браузера (`https://smnvda.ru` открывается с валидным сертификатом, замок закрыт)
- Известное некритичное предупреждение в Settings → Pages: `www.smnvda.ru is improperly configured` — `www` не имеет отдельной записи и попадает под wildcard `*.smnvda.ru` (A, старый сервер), поэтому ведёт не на GitHub Pages. На работу основного домена `smnvda.ru` это не влияет. Чтобы убрать — добавить в Jino отдельную запись `www.smnvda.ru` → CNAME `smnvda.github.io` (не трогая сам wildcard, он нужен другим сервисам)

### DNS-записи в Jino (⚠️ НЕ трогать почтовые)
В зоне `smnvda.ru` вперемешку лежат записи для сайта и для почты:
- **Не трогать**: `mail.smnvda.ru` (A), `smnvda.ru` (MX → mail.smnvda.ru), `smtp.smnvda.ru` (CNAME → smtp.jino.ru), `autoconfig.smnvda.ru` (CNAME), `_autodiscover._tcp` (SRV), `dkim._domainkey` (TXT) — держат корпоративную почту `@smnvda.ru`
- **Не трогать**: `n8n.smnvda.ru` (A) — отдельный сервис автоматизации, к сайту не относится
- **Не трогать**: `*.smnvda.ru` (A, wildcard на старый сервер) — не влияет на корневой домен, пока не мигрирован
